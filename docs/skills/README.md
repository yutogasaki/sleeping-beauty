# Skills

Use this folder for reusable repo-specific playbooks.

## When to create a Skill

Create a Skill when:

- a workflow repeats at least twice
- the workflow has hidden traps
- verification is easy to forget
- the work spans product, design, code, and operations

## What a Skill should contain

- trigger
- required inputs
- expected outputs
- recommended workflow
- verification
- known traps
- split or retire conditions

## Naming

Use concise workflow names:

- `admin-moderation-upgrades.md`
- `release-readiness-checks.md`
