# Tasks

Use this folder for active or upcoming work that benefits from a written brief.

## When to create a task file

Create a task file when:

- the change spans multiple files
- acceptance criteria matter
- verification is non-trivial
- design, product, and operational concerns overlap
- the work might continue across multiple sessions

## Naming

Use:

`YYYY-MM-DD-short-title.md`

Example:

`2026-03-13-admin-bulk-moderation.md`

## Lifecycle

1. Create the task before or at the start of implementation.
2. Keep it narrow and current.
3. When complete, write a matching record in `docs/done/`.
4. Remove stale or abandoned tasks, or mark them clearly as paused.
