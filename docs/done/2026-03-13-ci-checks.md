# Done: CI Checks

## What Changed

- Added a GitHub Actions workflow at `.github/workflows/ci.yml`.
- The workflow runs `npm ci`, `npm run test`, `npm run lint`, and `npm run build` on both push and pull request events.
- Updated repo docs so the baseline verification language matches the new automated checks.

## Why

- Baseline verification should not rely only on local discipline.
- Matching local and CI checks reduces surprise when pushing and makes the repo easier to operate across contributors.

## Verification Run

- `npm run test`
- `npm run lint`
- `npm run build`

## Residual Risks

- CI currently checks only the baseline Node workflow and does not cover browser-based UI flows.
- The workflow pins Node 20 explicitly; if the repo upgrades runtimes later, CI will need to move with it.

## Follow-ups

- Add branch protection so the CI check must pass before merge.
- Consider a second workflow later for preview-safe browser or screenshot checks if UI regressions become a recurring risk.
